# CLAUDE.md

Guidance for working in this repository.

## What this is

A single-page grade tracker for four Fall 2026 courses (SOCIOL 1197, GENED 1089, ITAL 10, STAT 100). Everything lives in `index.html`: inline CSS, markup and one IIFE script. There is no build step, package manager, framework, backend or test suite. Open the file in a browser to run it.

There is **no Base44 SDK** (or any other SDK/npm dependency) in this codebase, and no entity schema files. The data model is the plain JSON object described below. External resources are limited to Google Fonts.

## Data model

The whole app state is one object; there are four record shapes, not separate entities or tables.

**State** `{ v: 1, courses: Course[] }`

**Course**
- `id`: `"soc" | "gen" | "ita" | "sta"` (also the tab key)
- `code`, `name`, `who`: display strings
- `color`: suffix for the `--c-*` CSS variable
- `scale`: `[min, letter][]` (`HARVARD` or `ITALIAN`); `scaleNote`: string
- `cats`: `Category[]`
- `items`: `Item[]`
- `notes`: `string[]` (syllabus policies)
- `rev?`: seed revision, used by `migrate()` (STAT 100 is at 3)
- `placeholder?`: shows a "weights are placeholders" banner (no course sets it currently)

**Category** `{ id, name, weight /* percent */, drop /* number of lowest scores dropped */ }`

**Item** (graded assignment or to-do)
- `id`: generated by `id()`
- `cat`: category id, or `"_task"` for to-dos
- `name`, `due` (`YYYY-MM-DD` or `""`), `note`
- `score`, `whatIf`: raw strings, parsed by `parseScore` (`92`, `92%`, `18/20`, or a letter that maps to the middle of its band)
- `done`: boolean. Seeded items with past due dates start as done, and entering a valid score sets it.
- `task`: true for to-dos. These are excluded from grade math but shown in the due-date lists.

## Grade calculation

`compute(course, mode, fill)` averages each category (after dropping the lowest `drop` scores), then takes a weighted average over the categories that have any value. The weights are renormalised, so blank categories don't count against you. `mode: "whatif"` falls back to `whatIf` for ungraded items; `fill` assumes that percentage for anything still blank. `needed()` solves for the uniform average on the remaining work that reaches a target by interpolating between `fill = 0` and `fill = 100`.

## Persistence

There are two stores with the same `{ kind, load(), save(data) }` interface:

- `localStore`: `localStorage["fall2026-gradebook"]`. UI preferences are stored under `fall2026-gradebook-tab` and `gb-hide-done`.
- `cloudStore()`: used only when the page runs as a Claude artifact. It calls `window.claude.use("db")` and `window.claude.use("user")`, then reads and writes the doc `data/users/<uid>/gradebook`. This is the only external runtime API the app uses.

`boot()` renders from the seed or the local copy right away, then switches to the account copy when it loads. Saves are debounced by 700 ms and always mirror to `localStorage` as well.

## Making changes

- Course content changes (dates, weights, items) go in `seed()`. Already-saved data keeps the old seed unless you bump that course's `rev`. `migrate()` replaces a course only if the user has entered no scores or what-ifs in it; anything more careful needs a course-specific branch like the STAT 100 rev-3 one.
- Re-rendering replaces `#view.innerHTML` and restores focus by element `id`, so new inputs need stable, unique `id`s.
- Escape every user or seed string with `esc()` when interpolating into HTML.
- Keep the file self-contained. External scripts may only be loaded from approved CDNs with pinned versions; stylesheets only from Google Fonts.
